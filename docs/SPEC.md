# SPEC — Manga Record（重構版）

## 一句話描述

多使用者的漫畫追蹤工具。每人各自註冊帳號，記錄自己看到第幾話／第幾卷，以及追完後的推薦指數；漫畫目錄（書名、分類）全站共用，同一部漫畫不會被不同使用者重複建立。

## 背景

延續自 `comic-vibe`（單人版，Vue3 + Lambda + DynamoDB）的重構專案。重構動機：
1. 練習新技術棧：Python / FastAPI / PostgreSQL / Terraform / EC2 + Docker
2. 從單人擴充為多使用者系統
3. 漫畫目錄改為全站共用資料，避免重複輸入同一部作品

與舊專案（`comic-vibe/` / `infra/`）平行開發，不動舊專案的程式碼。舊系統資料在新系統穩定後才搬遷（見 `docs/TASKS.md`）。

## 使用者

- 開放註冊，任何人都可以建立帳號（帳號＋密碼，無 email 驗證）
- 每個使用者只看得到自己的收藏清單與進度
- 漫畫目錄（書名、分類）是全站共用資料，所有使用者共享同一份

## 核心功能

- 註冊 / 登入（JWT）
- 漫畫收藏列表（卡片式，畫面沿用 `comic-vibe` 現有風格）
- 新增收藏時輸入書名 → 對全站漫畫目錄做**模糊查詢**（繁簡通用，如「進擊」「进击」都查得到）：
  - 有找到既有漫畫 → 選取後帶 `manga_id` 建立收藏
  - 沒找到 → 只送書名，後端自動先建立新的漫畫目錄項目，再建立收藏
- 收藏可編輯：狀態、卷數、話數、評分
- 狀態：待看 / 追讀中 / 棄坑 / 已追完（四選一，per-user）
- 分類：熱血 / 懸疑 / 冒險 / 愛情 / 輕鬆 / 競技 / 復仇 / 生活 / 其他（九選一，屬於漫畫本身，全站共用）
- 評分 1–5 星，任何狀態下都可以填（不強制只有「已追完」才能評分）
- 刪除收藏（不會刪除全站漫畫目錄項目，其他使用者可能還收藏著）

## 明確不做（這階段）

- Email 驗證、忘記密碼流程
- AI 推薦功能（沿用舊系統的部分整支捨棄）
- 社交、分享、留言、多人協作
- 自訂分類、多標籤
- 漫畫目錄項目的編輯 / 刪除 API（新增流程之外的目錄維護，之後再評估）

## 與舊系統（comic-vibe）的差異對照

| 項目 | 舊系統 | 新系統 |
|---|---|---|
| 使用者 | 單一密碼，只有自己 | 開放註冊，多使用者 |
| 漫畫資料 | 每人（其實只有一人）各自一份 `Manga` | 全站共用 `manga` 目錄 + 每人各自 `collection` |
| status | 屬於 `Manga` | 屬於 `collection`（per-user） |
| rating 規則 | 僅 `completed` 才允許非 null | 不限制，任何狀態都可評分 |
| 分類 | 5～7 類 | 9 類（新增「復仇」「生活」） |
| 密碼儲存 | SSM SecureString（單一密碼字串） | bcrypt/argon2 雜湊，存 `member.password_hash` |
| 技術棧 | Vue3 + Lambda + DynamoDB + CDK | Vue3 + FastAPI + PostgreSQL(RDS) + Terraform + EC2/Docker |
